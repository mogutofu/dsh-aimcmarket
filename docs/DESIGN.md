# AIMCmarket 设计文档（经济模型 + 公式 + 数值 + 不变量）

这份文档写给两类人：想改数值/加功能的开发者，和想知道"钱到底怎么来的"的服主。
所有数字都能在代码里找到出处，下面每条都标了对应文件，方便对照。

## 0. 一句话结构

AIMCmarket 是一个**纯服务端**的模拟经济：商品市场、10 家 NPC 上市公司、3 只基金、银行、
玩家公司 + IPO、期货、期权、政府/央行、新闻。玩家用 `/ex` 命令和聊天跟"市场先生"打交道。

AI 干三件事：把自然语言翻成订单参数、写新闻/财报/招股书文案、扮演政府和央行提政策建议。
**AI 不碰钱**：价格、余额、扣款、发货、保证金、交割、政策落地全部由模组本地计算和校验，
AI 的返回一律当"建议"，过 schema 和边界校验才会生效。

## 1. 时间口径（三套，代码里不许混用）

| 口径 | 用途 | 默认值 | 代码 |
| --- | --- | --- | --- |
| 现实时间 | 工资、打工冷却、签到、AI 限流、新闻 | 毫秒 | `Account` 里的 `lastWorkAtMs` 等 |
| 市场 tick | 价格、利息、基金净值、盯市、政府指标 | 5 现实分钟 | `MarketClock.tick()` |
| 交易日 | 财报、分红、定期到期、期货/期权到期、IPO 锁定 | 60 现实分钟 = 12 tick | `MarketClock.day()` |

- 1 周 = 7 交易日 = 7 现实小时。
- 文档和代码注释里：金融模块的"天"= 交易日，收入模块的"天"= 现实天（UTC 日序号）。
- 配置项 `market.tickMinutes` 和 `market.tradingDayMinutes` 改了之后，所有按天/按 tick 的公式
  自动跟着变（`ticksPerDay = tradingDayMinutes / tickMinutes`）。

## 2. 货币与账户

### 2.1 货币

- 显示单位「币」，内部 `long` 存**分**（1 币 = 100 分），显示两位小数。
- 禁止用 `double` 累加余额；比率（利率、波动率、税率）用 `double`，算完立刻四舍五入回 `long`。
- 所有加减乘走 `Math.*Exact`/`util.Cents`，溢出直接抛异常（说明有 bug）而不是静默截断。

### 2.2 账户体系（复式记账）

`data/Ledger.java` 是唯一能改余额的地方。每个账户是一个 `BalanceAccount`：

| 账户 id | 含义 | 允许为负 |
| --- | --- | --- |
| `player:<uuid>` | 玩家钱包 | 否 |
| `bank:<uuid>` | 玩家银行存款（活期 + 定期本金） | 否 |
| `company:<id>` | 玩家公司现金 | 是（负了才会破产） |
| `fund:FND0x` | 基金现金（净值 = 现金/份额） | 否 |
| `gov:budget` | 政府预算 | 否 |
| `market:maker` | 做市商/清算账户（点差、保证金、理财收益的对手方） | 是 |
| `fee:pool` | 手续费池 | 否 |
| `sys:issued` | 净发行（负数，绝对值 = 流通货币总量） | 是 |

每笔资金变动都写一条 `ledger.jsonl`：

```json
{"seq":12,"at":1700000000000,"kind":"trade.buy","actor":"Steve","memo":"买入 铁锭",
 "legs":[["player:xxx",-3672],["sys:issued",3672]]}
```

**规则**：所有腿加起来必须等于 0。发钱 = 从 `sys:issued` 借出；销毁 = 还回 `sys:issued`。

- 买入商品：玩家付钱 → 全销毁（商品是实物价值，点差就是货币回收）。
- 卖出商品：系统增发给玩家。
- 缴税：转进 `gov:budget`；手续费：转进 `fee:pool`。
- 存款利息：增发；贷款利息/坏账：销毁。

### 2.3 不变量（selftest 逐条查）

1. **记账平衡**：`Σ(所有账户余额) = 0`（含 `sys:issued`），误差 0 分；
   重放 `ledger.jsonl` 后每个账户余额必须和内存一致。
2. **期货零和**：每笔持仓都有 `market:maker` 当对手方，`Σ(玩家平仓盈亏) + maker 盈亏 = 0`
   （不含手续费；手续费另进 `fee:pool`）。
3. **期权**：买方权利金 + 卖方权利金 = 0（一进一出）；到期内在价值的支付方是 `market:maker`，
   买卖双方结算后 maker 净额为 0（除非卖方保证金不足，差额由 maker 承担，记 ledger）。
4. **基金**：`净值 × 总份额 = 基金现金`（误差 ≤ 1 分，因为净值是按现金/份额反算的）。
5. **公司**：`公司现金 + 股东权益 ≈ 资产`；IPO 前后创始人股份价值不会凭空变大
   （发行价按发行后总股本折）。
6. **银行**：存款利息记为增发、贷款利息/坏账记为销毁，都在 ledger 里有据可查。
7. 新玩家 1 小时现实时间赚 300–500 币；每周货币净增 ≤ 5%（政府政策可短期放宽）。

## 3. 收入（现实时间口径，`engine/IncomeService`）

| 途径 | 规则 | 数值 |
| --- | --- | --- |
| 在线工资 | 每在线 30 分钟发 50 币，每现实日最多 8 次 | `salaryMinutes=30`、`salaryAmount=5000 分` |
| 打工 `/ex work` | 冷却 10 分钟，随机 30–80 币，5% 双倍，每日最多 20 次 | `workMin=3000`、`workMax=8000` |
| 签到 `/ex daily` | 每现实日 1 次，连续签到 10/15/20/25/30 币封顶，断签重置 | `dailyBase=1000`、`dailyStep=1000`、`dailyMax=3000` |
| 卖物品 | 按 ask 的 60% 回收 | `sellRatio=0.60` |
| 金融收益 | 股息、基金、存款利息、期权权利金、期货盈亏 | 见下文 |

签到第 n 天金额 = `min(dailyMax, dailyBase + (n-1)*dailyStep)`。第 1 天 10 币，第 3 天 30 币封顶。

## 4. 商品市场（`engine/PriceEngine`、`engine/TradeService`）

### 4.1 目录

- `config/aimcmarket/catalog.json`，首次启动从 jar 内置资源生成，当前 **135 项**（`tools/gen-catalog.mjs` 生成）。
- 每项：`{"id":"minecraft:iron_ingot","name_zh":"铁锭","aliases":["铁","iron"],"basePrice":1200,"volatility":0.02,"liquidity":12000,"enabled":true}`
- `basePrice` 单位分；`liquidity` 也按分算，越大越抗冲击。

### 4.2 价格模型（每 tick）

```
P_{t+1} = P_t * exp( θ*(ln(basePrice) - ln(P_t)) + σ*N(0,1) + impact ) * eventMultiplier
```

- `θ = 0.05`（均值回归速度），`σ = 条目 volatility`（默认 0.02）
- `impact = clamp(-0.02 * netBuyValue / effectiveLiquidity, -0.08, +0.08)`
  - `effectiveLiquidity = liquidity × 政府流动性政策倍数`（`GovernmentStore.liquidityMultiplier`）
- `eventMultiplier` = 新闻事件乘数（`[0.85, 1.20]`，持续 3–12 个 tick）的乘积，夹在 `[0.70, 1.30]`
- 结果夹在 `[basePrice*0.25, basePrice*4]`，且 ≥ 1 分

### 4.3 买卖价与规则

- 买价 `ask = P * (1 + askSpread)`，`askSpread=0.02`
- 回收价 `bid = P * bidRatio`，`bidRatio=0.60`
- 政府补贴/关税是对 ask/bid 再乘一个系数（见第 10 节），不改变 `P` 本身
- 下单校验：单物品 1–576 个；单笔 ≤ 5000 币；余额够；每人 1 单/3 秒；`admin.freeze` 时拒绝
- 成交：扣钱 → 发物品（背包满掉脚下）→ 失败回滚（`TradeService` 只管钱，物品由命令层发）

  - 价格夹在 `[初始价*0.10, 初始价*10]`

### 5.2 交易

- `/ex stock buy|sell <代码> <股数>`，T+0、整数股
- 手续费 0.2%（最低 1 币）+ 交易税（默认 0.5%，政府可调）：手续费进 `fee:pool`，税进 `gov:budget`
- 成交价 = 当前 `priceCents`；买卖双方是玩家和 `market:maker`
- 大盘指数：按流通市值加权，基点 1000.00；每个交易日快照，用于 7 交易日涨跌幅

### 5.3 分红与财报

- 每 7 交易日：`每股分红 = round(股价 × 年化股息率 × 7/365)`，持股不足 1 交易日不发
  （NPC 公司分红由系统增发；玩家公司分红从公司现金出，见 7.5）
- 每 7 交易日 AI 生成财报 `{revenueCents, profitCents, outlook, headline}`，outlook 影响下周期漂移；
  AI 不可用用内置模板（按股价动量/行业景气给 up/flat/down）
- `/ex stock info <代码>`：价格、涨跌幅、持仓、分红、最近财报

| 代码 | 名称 | 组合 | 目标年化 | 日波动 |
| --- | --- | --- | --- | --- |
| FND01 | 稳健基金 | 60% 债券(年化 4%) + 40% 股票指数 | 4% | 1.0% |
| FND02 | 平衡基金 | 50/50 | 6% | 1.8% |
| FND03 | 激进基金 | 20% 债券 + 80% 股票指数 | 9% | 3.0% |

- 净值从 1.0000 起。**净值 = 基金现金 / 总份额**，所以 `净值 × 总份额 = 基金现金` 恒成立。
- 每个 tick 给基金账户记一笔组合收益（增发）或亏损（销毁）：
  `tick 收益 = 债券权重×4%/365/ticksPerDay + 股票权重×指数 tick 收益 + 噪声`
  噪声 = `日波动/√ticksPerDay × N(0,1) × 0.25`
- 申赎按**下一个 tick 的净值**成交；手续费 0.5%；持有不足 1 交易日赎回再加收 2%
- `/ex fund list|buy <代码> <金额>|sell <代码> <份额>|info <代码>`

## 7. 银行（`data/BankStore`、`engine/FinanceService`）

- 活期年化 = `max(政策利率 − 1.5%, 0.1%)`，按**分钟**计息（每个 tick 用经过的分钟数累计，微分余数保留）
- 定期：7 交易日 = `政策利率 + 1.5%`；30 交易日 = `政策利率 + 3.0%`；到期本金回活期、利息增发；
  提前支取按活期利率重算
- 贷款：年化 = `政策利率 + 8%`，按交易日计息，额度 = `min(5000 币, 30 天平均日收入 × 3)`
  （日均收入 = 累计收入 / 账户存在天数）
- 信用分：初始 600，按时还款 +5（上限 850），逾期每天 −30（下限 300）
- 逾期：余额不足自动从活期扣；扣不到记逾期并扣信用分

| 行业代码 | 中文 | 基础日营收（分） |
| --- | --- | --- |
| mining | 采矿 | 50,000（500 币） |
| farming | 农业 | 35,000（350 币） |
| manufacturing | 制造 | 65,000（650 币） |
| trading | 贸易 | 42,000（420 币） |
| service | 服务 | 38,000（380 币） |

### 8.2 员工与日结

- 招聘费 200 币/人，日薪 20 币/人（交易日结算），上限 `5 + level*3`；裁员不退招聘费
- 每个交易日：

```
营收 = base[行业] × (1 + 0.08 × 员工数) × 行业景气 × 口碑 × random(0.9~1.1)
成本 = 员工日薪 + 营收×5%（维护费）+ 利润×10%（公司税，政府可调）
净利润 = 营收 − 日薪 − 维护费 − 公司税
```

- 记账：营收由系统增发进公司现金 → 日薪/维护费销毁 → 公司税进 `gov:budget`；
  净利润=营收−各项成本，留在公司现金里（可以为负）
- 口碑：初始 1.0，按时发薪 +0.01，欠薪 −0.05，夹在 `[0.6, 1.4]`
- 公司现金为负且连续 3 个交易日净利润为负 → 破产：员工清退、公司关闭、股票退市、CEO 信用 −100
- 估值：`max(5000 币, 公司现金 + max(0, 30 日平均日净利) × 120)`，每个交易日更新
- 分红：CEO 可设 `dividendRatio`（0–80%），每 7 交易日把最近一日净利润×比例按持股比例发给股东；
  `public` 流通股的分红进 `market:maker`

## 9. IPO、上市与退市（`engine/IpoEngine`）

### 9.1 条件（全部满足）

- 等级 ≥ 3；创建 ≥ 7 交易日
- 最近 7 交易日平均日净利 > 0；估值 ≥ 50,000 币
- CEO 持股 ≥ 51%；公司现金 ≥ 0
- 承销费 = `max(100 币, 估值 × 3%)`，从公司现金扣（销毁）

### 9.2 流程

1. `/ex ipo apply <流通比例>`：比例 10%–49%
   - `发行价 = 估值 / 发行后总股本`（等价于 `估值 / (原股本/(1-流通比例))`）
   - AI 生成招股书（`task=prospectus`），公告 1 交易日
2. `/ex ipo confirm`：新股上市，募资（新股数 × 发行价）增发进公司现金；
   CEO 股份被稀释（持股数不变、总股本变大），**锁定 30 交易日**
3. 股票进入交易所，代码 `P` + 3 位序号（P001…），可像 NPC 股票一样买卖/分红

### 9.3 上市后

- 股价用同一价格引擎，基准价 = 发行价，`σ = 2.5%`
- 财报每 7 交易日按公司真实营收/利润生成
- 再融资：`/ex company raise <金额>`，按当前股价 9 折向 NPC 机构发行，单次稀释 ≤ 20%，冷却 7 交易日
- 退市：股价 < 1.00 币连续 7 交易日，或破产 → 退市，股份按最后价 0 结算，CEO 信用 −100

## 10. 期货（`data/FuturesStore`、`engine/FuturesEngine`）

- 标的：IRON 铁锭、GOLD 金锭、DIAMOND 钻石、EMERALD 绿宝石、WHEAT 小麦（现价 = 商品市场 ask）
- 合约：1 手 = 64 个物品；到期 7/14/30 交易日后；现金交割
- 合约价：`F = S × (1 + carry × daysLeft/365)`，`carry = 5%`；到期时归 S
- 保证金：开仓名义价值 10%，维持 5%；每 tick 盯市：

```
多头 PnL = (F_now − F_entry) × 64 × 手数
空头 PnL = −多头 PnL
权益 = 初始保证金 + 累计未实现盈亏
```

- 权益 < 维持保证金 → 追保通知，5 分钟内补足，否则强平（按当前价反向平仓，扣 0.1% 强平费）
- 手续费：开/平各 0.05% 名义价值 + 交易税（进 `gov:budget`）
- 到期：现金交割，`结算 = max(0, 保证金 + (S_T − F_entry) × 64 × 手数)`（多头；空头相反），结算后合约删除

## 11. 期权（`data/OptionsStore`、`engine/OptionsEngine`）

- 标的：全部上市股票（NPC + 玩家公司）；欧式、现金交割
- 1 张 = 100 股；到期 7/14/30 交易日；行权价 = 现价 −10%、−5%、0、+5%、+10% 的 5 档网格
- 定价：Black-Scholes

```
d1 = (ln(S/K) + (r + σ²/2)T) / (σ√T)
d2 = d1 − σ√T
call = S·N(d1) − K·e^(−rT)·N(d2)
put  = K·e^(−rT)·N(−d2) − S·N(−d1)
```

  - `r = 政策利率`；`σ = 股票日波动 × √365`（年化）；`T = 到期交易日 / 365`
  - `N(x)` 用 erf 近似（误差 < 1e-7）
- 交易：
  - 买方付权利金（给 `market:maker`）
  - 卖方收权利金、缴保证金 `max(20% 名义, 权利金×3)`
  - 可提前平仓：按当前 BS 价反向成交，手续费 0.2%
  - 到期：内在价值 `max(0, S_T−K)`（call）/ `max(0, K−S_T)`（put）× 100 × 张数，现金结算；
    买方由 `market:maker` 支付，卖方从保证金/钱包支付
  - 卖方保证金 < 维持（10% 名义）→ 追保/强平

## 12. 政府 / 央行（`data/GovernmentStore`、`engine/GovernmentEngine`）

### 12.1 宏观指标（每 tick 更新，`/ex gov status` 可见）

| 指标 | 定义 |
| --- | --- |
| 货币总量 M | 所有账户余额之和（= `-sys:issued`） |
| 通胀率 | CPI 篮子（按 liquidity 加权的全目录价格指数）7 交易日涨幅 |
| 大盘指数 | 上市股票加权指数，及 7 交易日涨跌幅 |
| 平均财富 | 在线玩家余额中位数 |
| 政府预算 | `gov:budget` 余额 |
| 就业指数 | 所有公司员工总数 / 公司容量 |
| 市场活跃度 | 7 交易日成交额 |

### 12.2 压力分（0–100）与调用条件

```
压力分 = min(|通胀−3%|/10%, 1) × 25        // 通胀偏离
       + min(max(0, −指数7日涨跌)/15%, 1) × 25   // 大盘跌
       + 预算分 15                        // 预算 < 0 得 15，< 1000 币得 10
       + 财富分化 10                      // 中位财富 < 人均/3
       + (1 − 就业) × 15
       + min(1 − 7日成交额/1000币, 1) × 10  // 流动性
```

- 距离上次 AI 政府决策 ≥ 5 现实分钟，或压力分 ≥ 60，才调用 AI（省 token）
- 否则本轮只记录 `checkedAt`，不调 AI

### 12.3 AI 返回与本地兜底

AI 返回：

```json
{"action":"none|rate_cut|rate_hike|welfare|stimulus|austerity|subsidy|tariff|liquidity|min_wage",
 "params":{"bp":25,"amountCents":100000,"sectors":["工业"],"ratio":0.02,"days":3,"target":"minecraft:iron_ingot"},
 "reason":"一句话理由","announcement":"给玩家看的公告（可为空）"}
```

AI 不可用/超预算/结果不合法时的本地规则表：

| 条件 | 本地政策 |
| --- | --- |
| 通胀 > 8% | 加息 50bp |
| 通胀 < 0% | 降息 50bp |
| 指数 7 日跌 > 15% | 流动性支持（ratio 0.5） |
| 预算 > 5000 币且指数 7 日下跌 | 刺激（预算 5%，3 交易日） |
| 就业 < 0.4 | 福利（每人 100 币） |
| 其它 | `none` |

### 12.4 政策表（校验 + 生效 + 冷却）

| action | 参数 | 效果 | 边界 / 冷却 |
| --- | --- | --- | --- |
| rate_cut / rate_hike | bp ∈ {25,50,75,100} | 政策利率 ±bp，联动存贷利率 | 0–10%；同方向 6 交易日只一次 |
| welfare | amountCents | 给中位财富以下的在线玩家发钱，政府预算扣 | 每人 ≤ 500 币；预算不足拒绝；24 现实小时 1 次 |
| stimulus | amountCents, sectors, days | 指定行业景气 +5%（days 交易日），预算扣 | 预算 ≥ 金额；12 现实小时 1 次 |
| austerity | ratio ≤ 2% | 交易税 +ratio | 每 12 现实小时 1 次；总税 ≤ 5% |
| subsidy | target, ratio ≤ 20%, days | 该商品 ask 降价 ratio，持续 days 交易日 | 每 12 现实小时 1 次 |
| tariff | target, ratio ≤ 20%, days | 该商品 ask 涨价 ratio，持续 days 交易日 | 每 12 现实小时 1 次 |
| liquidity | ratio ≤ 1.0 | 做市商流动性 ×(1+ratio)，降低冲击 | 每 12 现实小时 1 次 |
| min_wage | amountCents 10–50 币 | 公司日薪下限，同时提高员工产出 | 每 24 现实小时 1 次 |

- 所有政策写 `government.json` + ledger + `news.json`，广播 `[政府] ...`
- 预算不足：政策拒绝、记录"政府：预算不足"、**不广播**
- `/ex gov status|budget|policies|history`；`/ex admin gov set <field> <value>` 仅 OP

## 13. 新闻（`engine/NewsEngine`）

- 每 15 现实分钟生成一条（AI `task=news`；AI 不可用用内置模板池）
- 影响 1–3 个商品/股票，`multiplier ∈ [0.85, 1.20]`，持续 3–12 tick
- 政策、财报、IPO、破产也会自动生成新闻条目

## 14. AI 接入（`ai/MarketAi`）

三级降级：

1. `ai.enabled=false` → 本地解析/本地规则
2. `ai.mode=auto|exchange` → `POST /mc-exchange`（严格 JSON，task = parse/news/report/prospectus/government）
3. exchange 不可用（404/超时/坏 JSON/`ok:false`）→ `POST /mc-ai`（自然语言，返回文本里抠 JSON）
4. 本地解析器（`ai.LocalParser`）/ 本地规则表兜底

- 固定身份：`{"player":"AIMCmarket","uuid":"00000000-0000-0000-0000-00000000a1c0"}`
- 玩家消息进 AI 前截断 200 字符、去换行；AI 返回只作建议，必须过 `ai.AiJson` schema 校验
- 每玩家 AI 调用 1 次/2 秒；全局 60 次/小时；超出只用本地逻辑
- HTTP 在 daemon 线程池（2 线程）跑，结果 `server.execute(...)` 切回主线程

## 15. 持久化

`world/aimcmarket/` 下 11 个文件（UTF-8 JSON，带 `"schema":1`）：

```
accounts.json  market.json  stocks.json  funds.json  bank.json
companies.json futures.json options.json government.json news.json
ledger.jsonl
```

- 写盘：临时文件 + 原子 move；每个 market tick 和 ServerStopping 落盘；单文件坏了改名备份并重置，
  **绝不导致服务器启动失败**
- 读盘：缺字段用默认值，不抛异常

## 16. 已知简化（0.1.0 明确不做 / 简化）

- 不做客户端 mod、GUI 容器、真实联网行情、外部交易 API、数据库/Redis。
- NPC 公司的"财报数字"是围绕股价/行业景气合成的，不是真的财务模型。
- 基金组合收益是指数收益 + 债券收益 + 噪声的合成，不持有真实股票。
- 期货/期权的对手方永远是 `market:maker`（不撮合玩家对玩家），所以"零和"按
  `Σ玩家盈亏 + maker 盈亏 = 0` 结算。
- 债券、保险、并购、收藏品是 P2，0.1.0 不做。
- 限价单只做了 P1 的最小形态，0.1.0 未实现。
